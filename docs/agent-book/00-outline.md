# 《一个靠谱的 AI 同事》全书大纲

> 副标题：企业级 Agent 设计实战
> 版本：v0.7（飞书 IM 归入能力·UI；Human Channel 协作+边界双提）

---

## 一、这本书写给谁

- **目标读者**：有技术背景、想系统理解并上手企业级 agent 的开发者。你不需要会写代码，但需要能看懂「为什么这么设计」。
- **不写什么**：不贴代码、不讲模型训练、不堆算法公式、不画技术架构大图。
- **写什么**：设计思想、模块职责、踩过的坑、以及那些让系统「从能跑到能扛」的**巧思**。

## 二、全书的一个核心比喻

把企业级 agent 当成——**「一个能力很强、刚入职、值得好好培养的新同事」**。

- 他天生有一个聪明的大脑（模型）。这本书要做的，就是像带一个高潜力新人一样，帮他把本事一样样长出来：培养他善于总结的能力（记忆）、给他需要的资源和工具（能力）、培养他的表达能力（UI）、共建和共享公司的知识资产和经验（知识库）、锻炼协作能力（协作）、让他敬畏规章（边界）、做好公司的管理制度建设（治理）；
- 这条路，从内到外走五步：先让他「想得清、记得住」（智力），再让他「做得成、说得清」（能力），再让他「合得来」（协作），给他「立工作纪律」（边界），最后把「安全、健康、谁来管」这些系统级的事管起来（治理）。

全书每一章，都在回答「怎么帮这个高潜力的新同事，长成一个靠谱的骨干」。

## 三、全书结构（开篇 + 5 部分 · 18 章）

> **主线：智力（怎么想、怎么记）→ 能力（怎么做、怎么表达）→ 协作（怎么一起干）→ 边界（立规矩、守纪律）→ 治理（系统安全与运营）**
> 从内到外，对应「培养一个新人」的完整过程。每一章只归一个主题，不交叉、不重叠。
> ⚠️ 第六部分「测试」**待定，暂不写**，后续确认内容后再补。

### 开篇（2 章）

**第 1 章　从「写死的程序」到「会思考的 Agent」**（样章）
- 核心问题：程序、大模型、Agent 三者到底差在哪？
- 比喻：自动售货机 → 天才新人 → 靠谱同事
- 巧思预告：先记账再干活、两本账、多 agent 分工

**第 2 章　一张图看懂企业级 Agent**
- 核心问题：一个企业级 agent 由哪些模块拼成？各模块什么关系？
- 配图：全书地图（智力 / 能力 / 协作 / 边界 / 治理五层）

### 第一部分 · 智力：它怎么「想」、怎么「记」（3 章）

> 只讲一件事：agent 的「内在」——靠什么思考、靠什么记住。模型、上下文、记忆，都归在这里。

**第 3 章　一队大脑，而不是一个大脑（模型分类）**
- 不同模型各有所长：快的、强的、便宜的，没有「最好」，只有「最合适」
- 巧思：分层用模型——难的用贵的、简单的用便宜的；把「聪明的脑子」和「可靠的系统」分开

**第 4 章　一次对话，靠什么「接得上话」（session 上下文管理）**
- 上下文、状态、流式输出「说一半」时怎么管理；窗口装不下怎么办
- 巧思：事件缓冲——「集齐了再落账」，不全不落；给用户看的账 vs 给模型看的账

**第 5 章　把对话，变成「记得住的事」（记忆沉淀）**
- 什么该记、记在哪、谁能看；记忆也要分级；记多了会膨胀
- 巧思：云上的、个人的、项目的，边界清晰；先记账再干活（可靠）；工作总结式压缩（舍得忘）

### 第二部分 · 能力：它怎么「做」、怎么「表达」（4 章）

> 讲 agent 的「手脚」和「嘴」——它凭什么能把事做成，又能让你看得懂它在做什么。

**第 6 章　技能包：把能力装进去（skill）**
- 模型只会「说」，不会「做」；skill 就是它的手和脚
- 巧思：能力要「可发现、可描述、可校验」，不是越多越好；一个 skill 一个职责

**第 7 章　别人的 API，变成自己的工具（API 转 MCP）**
- 外部世界的接口五花八门，agent 怎么统一调用
- 巧思：把散落的 API 收拢成一套统一的「工具协议」，搜索 / 调用 / 摘要三步走

**第 8 章　听见、看见、说出来（多模态）**
- 语音、图像怎么接入；「听写」这件事比想象中难
- 巧思：把重活（转写）放到服务端，前端只负责收声音；不支持就优雅降级

**第 9 章　把想法，画给你看（UI 与交互）**
- agent 在「黑盒」里干活，人怎么看得见、信得过
- 巧思：流式渲染「边想边说」；工具调用链可视化——把它「查了库、调了工具、算了数」的过程透明地画出来；状态指示灯——「在想」和「卡住了」要一眼分辨；给人看的账全量留痕，给模型看的账精简压缩
- 走出 Web：飞书 IM 集成——对话界面不止网页，还要走进企业聊天工具，用户不用登录网页也能直接对话（飞书 IM 属 UI，归「能力」）

### 第三部分 · 协作：它怎么「一起干」（3 章）

> 讲 agent 与「别的 agent」「别的活」「共享的知识」怎么配合。也别漏了「人和 agent」的协作——agent 卡住了、拿不准了，得会向人求助、请人拍板（Human Channel 的协作面）。

**第 10 章　把知识，攒成公司的家底（知识库）**
- 知识库不是「临时翻看的手册」，而是公司的「知识资产」——像专利、客户名单、SOP 一样，越沉淀越值钱
- 巧思：检索不是关键词匹配，是「找最相关的那一页」；资产要持续维护、反复复用，才越滚越值钱

**第 11 章　一个人干不完，就分工（子 agent 调用）**
- 一个人既当医生又当护士的问题；专业分工
- 巧思：对话者 / 协调者 / 专家的三层分工，各管一摊

**第 12 章　那些要等一等的活（task 调度）**
- 有些活要跑几分钟，不能干等；排队、并发、可回收
- 巧思：一个「任务队列」把慢活和快活分开；每件任务都留一笔账，跑到哪一步、成没成、结果是什么，随时追得到

### 第四部分 · 边界：立一套工作纪律（3 章）

> 边界不是「设个护栏把模型挡住」，而是像管一个新员工一样，立一套工作纪律：先有**工作手册**（哪些能说、哪些不能碰），再要求**汇报**（干了什么、调了什么，要留痕可查），配**监督**（盯着它别想岔、别分心），最后有**评审**（关键动作要人来复核才放行）。这三章，就是这份「工作手册」里最要紧的三条纪律。

**第 13 章　守口如瓶，守住商业秘密与个人隐私（脱敏）**
- 要保护的对象就两类：企业的**商业秘密**（配方、报价、客户名单、未公开合同）和个人的**隐私**（身份证、手机号、病历、住址），怎么保证不被模型「不小心」说出去
- 巧思：在输入和输出两头设卡，先脱敏再进模型；日志只记「路」，不记「内容」

**第 14 章　先搞清楚，你到底想干什么（意图识别）**
- 一句话背后可能是十个意思；听岔了会干错活
- 巧思：先判「是不是任务、要不要规划」，再决定怎么干

**第 15 章　心无旁骛，只做最要紧的事（相关性检查）**
- 信息一多，模型就容易「分心」——跑题、抓不住重点、把次要的当主要的。它的注意力要始终放在「当前正确、优先级最高」的那件事上
- 巧思：相关性过滤——先分清「什么最要紧」，只喂真正相关的；信息不是越多越好，是「越专注、越聚焦越好」

### 第五部分 · 治理：系统级安全与运营（3 章）

> 边界管的是「模型」这个人的言行；治理管的是「整套系统」——谁有权限、干过什么、系统健不健康、花了多少钱、谁来管。安全审计、可观测性、后台管理，都归在这里。

**第 16 章　谁能干什么，钥匙放哪（安全审计）**
- 天才同事也有权限边界；谁的数据、谁的钥匙；干过什么要留痕
- 巧思：钥匙放保险柜（密钥管理），不写死在代码里；分层权限，最小授权

**第 17 章　看得见，才管得住（可观测性）**
- 一个能干的员工，也得「看得见」才管得住：工作进度到哪了、成果是什么、谁在负责、有没有跑偏——这正是企业里管理人和项目的基本功
- 巧思：把 agent 的「工作进度」和「工作成果」沉淀成一条可回放的轨迹（它在想什么、调了什么工具、产出了什么、花了多少 token）；小时粒度的埋点，看板按日/周/月/年聚合，支撑管理层对项目和人力做监督；全局在线指示灯，一眼看系统死活

**第 18 章　谁来管这个系统（后台管理）**
- 一百个人用，谁来管——这其实就是企业的「行政管理」：管人（谁能进来）、管权（谁能干什么）、管资源（谁能配什么模型）、管流程（邀请制怎么招人）
- 巧思：分级管理员（超级管理员 → 管理员 → 普通用户），对应企业的管理层级，每一级只做份内的事；每个后台入口都绑定权限，最小授权；邀请注册——入职由公司把关，不开放自注册，谁进来说了算

## 四、每章统一的结构（写作范式）

1. **一个生活化场景**：用比喻切入，先让读者「有感觉」
2. **它到底是什么**：把概念讲透，不讲代码
3. **为什么这么设计**：设计取舍与权衡
4. **一个巧思**：一个反直觉或点睛的设计点
5. **一张配图**：插画（比喻）或示意图（流程/结构）

## 五、配图风格约定

- **插画**（AI 生成，扁平/漫画风）：用于比喻、场景、人物化表达
- **示意图**（SVG，简洁）：用于流程、结构、对比、分层
- 每章 1–3 张，插画与示意图搭配使用
