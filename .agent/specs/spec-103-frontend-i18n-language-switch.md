# SPEC-103 纯前端国际化（i18n 翻译 + 语言切换）

> **SPEC-103** | Status: 设计中（立项，暂不深化）
> 日期：2026-09-18

## 1. 目标

1. **纯前端国际化**：前端全部 UI 文案翻译化（文案从 TSX 硬编码中抽离为语言资源），支持多语言界面。
2. **语言切换**：用户可在界面切换语言（默认中文），选择持久化，全站即时生效。

|-----------|:---:|------|

| — | — | 纯前端，无后端前置 |

## 2. 背景与动机

- 当前前端所有文案**硬编码中文**（TSX 内直接写死），无国际化能力。
- 产品面向上海外贸企业市场（见商业定位），存在英文界面需求。
- 语言切换与已有主题切换（SPEC-076）同属「用户偏好 + 纯前端」模式，实现路径可复用。

## 3. 方向（立项不展开，仅列范围与待定项）

### 3.1 范围界定

- **前端 UI 文案**：菜单、按钮、表单标签、提示、空态、错误信息等（`frontend/app/**`）。
- **不翻译**：LLM 对话内容、用户生成内容（知识库/记忆/artifact 内容）。
- **后端返回文案**（如审计日志 action 描述、通知内容、后端 error message 中文）：**纯前端无法翻译后端硬编码中文**——如何处理是重要决策点（见 §4）。

### 3.2 方向性设计

- 语言资源字典化（翻译文件，key-value，如 `zh.json`/`en.json`）。
- 全局语言状态（Provider/Context）+ localStorage 持久化，默认 `zh`。
- 语言切换入口 UI（与主题切换并列或就近），切换即时生效。
- 参考 SPEC-076 的防闪烁与持久化范式（`data-theme` → 类比 `lang`/`data-lang`）。

## 4. 待定决策点（立项列出，深化时逐一定稿）

1. **i18n 技术方案**：next-intl / i18next / 自研轻量 context+字典。倾向轻量（自研或 next-intl），待调研 Next.js App Router 兼容与 SSR 水合问题。
2. **支持语言范围**：起步 zh + en？（外贸场景推测双语起步，待确认）。
3. **后端中文文案处理**：①后端文案改为错误码/英文+前端映射 ②接受「后端返回中文仅中文界面显示」③后端随 Accept-Language 返回——涉及后端改动，与「纯前端」范围冲突，需定边界。
4. **SSR/水合**：App Router 下语言初始值的水合一致性（cookie vs localStorage vs 默认值）。
5. **翻译覆盖面**：全部页面 vs 主流程页面分批。

## 6. 可行性分析

| 检查项 | 结论 |
|--------|------|
| 是否需要新 DB 集合 | No（纯前端；语言偏好 localStorage） |
